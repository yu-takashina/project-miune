# サイトマップの登録と巡回

2026-10-14 時点の実装をそのまま仕様として書いたもの。

## 全体の流れ

1. 管理画面で sitemap.xml の URL を登録する。
2. スケジューラ、または画面の「今すぐ巡回」で sitemap.xml を読み、掲載 URL を `sitemap_pages` に同期する。
3. 掲載 URL のうち未取得のものを、1秒に1ページずつ取得して本文を保存する。
4. 日次で sitemap.xml を読み直し、増えた URL を追加し、外れた URL は設定回数に応じて削除する。
5. 週に1回、sitemap.xml を読み直したうえで、掲載中の全ページを取得し直して本文を更新する。

## サイトマップの状態

| 状態 | 値 | 意味 |
| --- | --- | --- |
| 確認待ち | `pending` | 登録直後。まだ sitemap.xml を読んでいない |
| 巡回中 | `crawling` | 未取得、再巡回の取り直し途中、または採用本文のベクトルがまだ無いページがある |
| 巡回済 | `completed` | 掲載 URL を取得し終え、ベクトルが必要なページはベクトル化済みか、同じ本文では成功しない失敗 |
| 取得失敗 | `failed` | 初回の読み込みで sitemap.xml を取得できなかった |
| 書式エラー | `invalid` | 初回の読み込みで sitemap.xml の書式が正しくなかった、または深さが上限を超えていた（深さエラー） |

- 一覧の状態の列は、`error_message` があればそれを赤字で出し、なければ状態名を出す（「巡回中」も赤字）。
- 2回目以降の読み込み（日次の読み直し、週次の再巡回、巡回済からの「今すぐ巡回」）で深さエラーになったときは、状態は「巡回済」のまま変えず、`error_message` だけを残す。一覧には「巡回済」ではなく深さエラーのメッセージが出る。次の読み込みが成功すると、メッセージは消えて「巡回済」の表示に戻る。

遷移:

- 確認待ち → 巡回中: 読み込みに成功し、取得するページがある
- 確認待ち → 巡回済: 読み込みに成功し、取得するページがない
- 確認待ち → 取得失敗 / 書式エラー: 読み込みに失敗した（深さエラーは書式エラーになる）
- 巡回中 → 巡回済: 掲載中のページを取得し終え、採用本文があるページはベクトルがあるか、同じ本文では成功しない失敗になっている
- 巡回済 → 巡回中: 日次の読み直しで新しい URL が見つかった、週次の再巡回が始まった、または「今すぐ巡回」を押した
- 取得失敗 / 書式エラー → 確認待ち: 「今すぐ巡回」を押した（すぐに読み込みをやり直す）

## 1. 登録

- 管理画面のサイトマップ一覧から URL を登録する。
- URL は http または https。登録済みの URL は登録できない（URL 文字列の SHA-256 で一意）。
- 登録時に sitemap をたどり、深さが上限を超えていればエラーを表示して保存しない。取得失敗や書式の不正は、ここでは止めずに「確認待ち」で保存する。
- 深さの問題がなければ「確認待ち」で保存する。掲載 URL の取り込みは、次の毎分の処理（最大1分後）。
- 外れた URL を削除するまでの回数（`absence_limit`）の初期値は 1 回。

## 2. sitemap.xml の読み込み

実装: `App\Jobs\InspectSitemap`、`App\Services\SitemapTreeReader`、`App\Services\SitemapUrlsetReader`

### 書式

- ルート要素が `urlset` または `sitemapindex` で、名前空間 `http://www.sitemaps.org/schemas/sitemap/0.9` を宣言していること。
- 各 `loc` が http または https の URL であること。1件でも不正な `loc` があれば、そのファイル全体を書式エラーとする。
- `loc` が1件もないファイルは書式エラー。
- `lastmod` などの `loc` 以外の要素は使わない。
- 外部エンティティは読まない（`LIBXML_NONET`）。
- ファイルサイズの上限はない。

### ネスト

- `sitemapindex` に載っている子 sitemap を再帰的に読む。
- 登録した sitemap を深さ 1 とし、深さ 5（`InspectSitemap::MAX_DEPTH`）まで読む。
- 上限より深い子 sitemap があるときは、その URL は読まず、読み込み全体を深さエラーにする。メッセージは「sitemap の深さが 5 を超えています。」。
- 登録時: フォームにエラーを出して保存しない。
- 確認待ちからの読み込み: 状態を「書式エラー」にし、`error_message` に残す。ページは同期しない。
- 日次の読み直し、週次の再巡回、巡回済からの「今すぐ巡回」: 状態とページは変えない。`error_message` に残す。再巡回は始めない。次の読み込みが成功したら `error_message` は消える。
- すでに読んだ sitemap の URL が上限より深い位置に再度出ても、深さエラーにはしない。
- 同じ sitemap の URL は1回だけ読む。
- 子 sitemap が1つでも取得失敗または書式エラーなら、その回の読み込みは全体を失敗とし、何も同期しない。

### 重複

- 掲載 URL は、全階層をまとめたうえで重複を除く。
- 重複の判定は URL 文字列の完全一致。末尾のスラッシュやフラグメント（`#`）の違いは別の URL として扱う。
- ページは sitemap ごとに一意（`sitemap_id` と URL の SHA-256）。別のサイトマップに同じ URL があれば、別の行として持つ。

### 同時に読み込まない

- 同じサイトマップの読み込みと同期は、同時に1つまで。毎分の確認待ちの読み込み、日次の読み直し、週次の再巡回、「今すぐ巡回」のどれにも効く。
- `InspectSitemap` がサイトマップごとのロック（キャッシュのロック、キー `sitemap-inspect:{id}`）を取ってから読む。ロックの期限は 600 秒（`InspectSitemap::LOCK_SECONDS`）。期限を過ぎても終わらない読み込みがあると、次の読み込みが重なることがある。
- ロックを取れなかった側は、sitemap.xml を読まず、状態もページも変えずに戻る。不在回数も数えない。
  - 毎分の処理: そのサイトマップを飛ばし、ほかのサイトマップは続ける。次の回に読み込む。
  - 日次の読み直し、週次の再巡回: そのサイトマップはその回は何もしない。週次の再巡回も始めない。
  - 「今すぐ巡回」: 再巡回を始めず、今の状態を返す。取得失敗 / 書式エラーから押したときは、確認待ちに戻したところで止まり、毎分の処理が読み込む。
- ロックの中で状態を読み直してから処理する。先に動いた側が確認待ちを巡回中に変えていれば、後の側は確認待ちとしての読み込みをしない。

### HTTP

- タイムアウトは 30 秒、接続タイムアウトは 10 秒。User-Agent は `miune`。
- 2xx 以外のレスポンスは取得失敗とする。

### 失敗したとき

- 初回（確認待ちからの読み込み）: 状態を「取得失敗」または「書式エラー」にし、エラーメッセージを保存する。
- 2回目以降（日次の読み直し、週次の再巡回、巡回済からの「今すぐ巡回」）: 状態もページも変えない。取得失敗と書式エラーは画面に出ない。週次の再巡回と「今すぐ巡回」は、そのあと前回までの掲載 URL で再取得を続ける。深さエラーだけは `error_message` に残り、再取得へ進まない。
- 取得失敗と書式エラーは自動では再試行しない。「今すぐ巡回」でのみやり直す。
- 読み込みに成功したとき、サイトマップの巡回日時（`sitemaps.crawled_at`）をその時刻にする。失敗したときは前回のまま残す。一度も成功していなければ空。
- サイトマップ一覧では、「削除までの回数」の右に `Y-m-d H:i` で出す。ページの取得日時とは別で、掲載 URL を取り直してもこちらは変わらない。

## 3. 掲載 URL の同期

読み込みに成功したとき、掲載 URL と `sitemap_pages` を突き合わせる。

### sitemap に載っている URL

- 新しい URL: 行を追加し、取得対象にする。
- 既存の URL: 何もしない。本文の再取得もしない。
- 一度外れて戻ってきた URL: 不在回数を 0 に戻し、掲載中に戻す。本文があれば再取得しない。なければ取得対象にする。

### sitemap から外れた URL

- 不在回数（`absence_count`）を 1 増やし、初めて外れたときは外れた日時（`unlisted_at`）を記録する。
- 不在回数が `absence_limit` に達したら、その行を削除する。
- `absence_limit` は 1〜5 回、または「削除しない」（`null`）。サイトマップ一覧で変更できる。
- 「削除しない」の場合、外れた URL は行として残り、検索には出ない。
- 読み込みに失敗した回は数えない。取得エラーで一斉に削除されることはない。
- 回数を減らしても、すぐには削除しない。次の読み直しで判定する。

## 4. ページの取得

実装: `App\Services\CrawlDueSitemapPages`、`App\Jobs\CrawlSitemapPage`

- 対象は、状態が「巡回中」のサイトマップの掲載中のページのうち、次のいずれかに当てはまるもの。ID 順に取得する。1回の実行では同じページを繰り返さない。
  - 未取得（`crawled_at` が空）
  - 採用本文があり、そのハッシュのベクトル行が無く、`embedding_failed_sha256` がその本文ハッシュではない
  - 再巡回中のサイトマップで、まだ取り直していない（ページ ID が `sitemaps.recrawl_after_page_id` より大きい）
- 1秒に1ページ（`INTERVAL_SECONDS`）。
- タイムアウトは 30 秒、接続タイムアウトは 10 秒。User-Agent は `miune`。
- HTTP ステータス、サイズ、本文、本文の SHA-256、取得日時を保存する。2xx 以外のレスポンスも保存する。本文は Content-Type または HTML の meta charset に従って UTF-8 に変換し、文字コード指定がなく UTF-8 でもない場合は日本語の主要な文字コードを判定する。`body_sha256` は変換後の保存本文から計算する。
- 保存する本文の meta charset は UTF-8 に書き換える。ヘッダと meta charset が食い違っていても、後から `sitemaps:extract` で抜くときに同じ文字コードで読める。
- 本文を UTF-8 に変換できなければ本文は保存せず、「文字コードを UTF-8 に変換できません。」とし、抽出状態を「抽出失敗」にする。
- 本文が 2MB（`CrawlSitemapPage::MAX_BODY_BYTES`）を超えたら本文は保存せず、「レスポンスが大きすぎます。」とする。
- 接続できなかったときは「取得に失敗しました。」とする。自動では再試行しない。
  - 一度も取得していないページ: 取得日時に今の時刻を入れる。
  - 取得済みのページ: 取得日時、本文、HTTP ステータス、抽出結果は前回のまま残す。
- 掲載中のページを取得し終え、再巡回中なら最後のページまで取り直し、採用本文のベクトルが無いページ（同じ本文では成功しない失敗を除く）も無くなったら、サイトマップを「巡回済」にし、`recrawl_after_page_id` を空に戻す。

### 本文の抽出

実装: `App\Services\ExtractSitemapPage`、`App\Services\ReadabilityTextExtractor`、`App\Services\TrafilaturaTextExtractor`、`App\Services\ExtractionComparison`

- UTF-8 に変換したレスポンスを保存できた直後に、Readability と Trafilatura で本文を抜く。保存したレスポンスは `body` に残す。検索の条件は変えない。
- 保存前の `body_sha256` と、今回の本文の SHA-256 が同じときは、抽出済み（`extracted_at` があり「抽出失敗」でない）なら抜かない。採用した本文と抽出状態は前回のまま残す。未抽出または「抽出失敗」なら抜き直す。本文が同じでも、採用本文のハッシュに一致するベクトル行が無ければ、抜き直さずにベクトル化する。採用本文が空（「本文なし」）のときはベクトル化しない。
- 本文が変わったときは、保存と同時に以前の採用本文、抽出状態、抽出日時を消してから抜き直す。抽出中に予期しないエラーが起きても以前の本文は残さず「抽出失敗」にする。
- 抽出が失敗しても、取得の成否は変えない。
- 採用は `ExtractSitemapPage::adoptedText()`。保存した本文は `SitemapPage::articleText()` で読む。
  - 両方の抽出器が空でない本文を返したときだけ比べる。空白を畳んだ文字3-gramの Jaccard 係数が 0.8 以上なら一致、未満なら不一致とみなす。閾値は `ExtractionComparison::MINIMUM_SIMILARITY`。
  - 一致したときは Trafilatura の本文を採用する。差は小さいので、どちらを使っても同じ本文とみなす。
  - 不一致の分岐は残し、将来はそこで ChatGPT に両方の本文を渡す。このプロジェクトはデモのため、課金を避け、その分岐では Trafilatura が抽出した文字列を返す。
  - 片方の抽出器だけ異常終了したとき、または片方だけ本文を見つけたときは、取れた側の本文を採用する。
- 抽出状態 `extraction_status` は次の2つだけ保存する。本文を採用できたときと未抽出のときは空。一致と不一致は保存しない。
  - 「本文なし」: 採用した本文が空文字。
  - 「抽出失敗」: HTML でないレスポンス、文字コードを UTF-8 にできないレスポンス、両方の抽出器が異常終了したとき。採用した本文は残さない。
- 保存するのは採用した本文 `article_text` だけ。Readability、Trafilatura、将来の ChatGPT が抽出した文字列は、それぞれは保存しない。
- 採用した本文が空でないときは、その SHA-256 を `article_text_sha256` に保存する。本文がないとき、空文字のときは空にする。保存のたびに `article_text` から計算する。
- 本文ハッシュが空ならベクトル化しない。ハッシュが空になった保存では、そのページのベクトル行をすべて消す。抜き直しの直前に本文を空へ戻すときだけは、ベクトル行を残す。
- ベクトルは `sitemap_page_embeddings` に保存する。同じページの行を複数持てる。今回の分割は本文全体の1行だけで、段落には分けない。行の順番は持たない。
- ベクトル化は取得の流れの中で行う。そこで止めるのは、レスポンスのハッシュが前回と同じで、採用本文のハッシュに一致するベクトル行があるときだけである。抽出した採用本文のハッシュが前回と同じときも、そのハッシュのベクトル行があるときだけ止める。どちらも無ければ OpenAI の埋め込み API（`text-embedding-3-small`、1536 次元）を呼ぶ。送る本文は先頭 4000 文字まで。チャット API は使わない。成功してから、そのページのベクトル行をすべて入れ替える。失敗したときは古い行を残し、取得と抽出の成否は変えない。
- API キーが未設定、または認証に失敗したときは、そのページのベクトル化だけを飛ばす。失敗ハッシュは残さない。タイムアウト、429、5xx も失敗ハッシュは残さない。ベクトル行が無いので、次にそのページを取得したときに API を呼び直す。長さ超過のように同じ本文では成功しない失敗は `embedding_failed_sha256` にその本文ハッシュを残す。その本文では、ベクトルが無くても API を呼び直さない。失敗メッセージは `embedding_error` に残し、入れ替えが成功したら両方空にする。
- 掲載URL一覧には、抽出状態の列も絞り込みも出さない。
- プレーンテキストの先頭行がページの `title` と一致するときは、比較の前にその行を落とす。
- Trafilatura はアプリイメージの `/opt/trafilatura` で動かす。HTML は標準入力で渡し、Trafilatura からは URL を取得しない。
- 本文を保存しなかったページ（大きすぎる、未取得）は抽出しない。大きすぎるページを取り直したときは、前回の抽出結果を消す。
- 保存済みの本文だけを後から抜くコマンドは `sitemaps:extract`。対象は本文があり、`extracted_at` が空、または「抽出失敗」のページ。本文を一度に読み込みすぎないよう10件ずつ処理する。定期実行はしない。保存済みの本文は UTF-8 なので、本文中の指定と UTF-8 の判定だけで処理する。採用本文のハッシュが変わったとき、または同じハッシュのベクトル行が無いときは、巡回と同じくベクトル化する。

### 再巡回

- 週次の再巡回と一覧画面の「今すぐ巡回」では、取得済みのページも取得し直す。
- 取得日時は消さない。レスポンスを受け取れたページだけ、本文と取得日時を上書きする。再巡回中も、画面のページの取得日時は前回の値のまま見える。
- 進み具合は `sitemaps.recrawl_after_page_id` で持つ。再巡回の開始時に 0 にし、1ページ取得するたびに、そのページの ID まで進める。成功しても失敗しても進むので、同じページを繰り返し取得しない。

## 5. 定期実行

実装: `routes/console.php`。`miune_scheduler` コンテナで `php artisan schedule:work` が動く（cron は使わない）。

| コマンド | 間隔 | 内容 |
| --- | --- | --- |
| `sitemaps:crawl` | 毎分 | 確認待ちのサイトマップを読み込み、未取得のページと、採用本文のベクトルが無いページを取得する。1回 55 秒（`BUDGET_SECONDS`）で打ち切り、残りは次の回に回す。止める条件に当てはまらなければ、その取得の中でベクトル化する |
| `sitemaps:refresh` | 月〜土曜 4:30 | 巡回済のサイトマップを読み直し、掲載 URL を同期する |
| `sitemaps:recrawl` | 日曜 4:30 | 巡回済のサイトマップを読み直して掲載 URL を同期し、再巡回を始めて「巡回中」にする。取得は `sitemaps:crawl` が1秒に1ページずつ行う |

- どれも重複起動しない（`withoutOverlapping`）。
- `sitemaps:recrawl` も sitemap.xml を読み直すので、日曜は `sitemaps:refresh` を動かさない。同じ日に2回読んで不在回数を二重に数えないため。
- `sitemaps:refresh` と `sitemaps:recrawl` の対象は「巡回済」だけ。「巡回中」のまま日をまたいだサイトマップは、その日の読み直しも再巡回もしない。
- 「確認待ち」の読み込みには 55 秒の打ち切りがかからない。

## 6. 今すぐ巡回

### サイトマップ一覧の「今すぐ巡回」

実装: `SitemapController::crawlNow`

1. 押した時点の状態が巡回中なら、何もしない。sitemap.xml もページも読まず、データベースは更新しない。
2. それ以外は、状態に応じて sitemap.xml を読む。
   - 巡回済: 読み直して同期する（日次の読み直しと同じ）。
   - 確認待ち: 読み込む。
   - 取得失敗 / 書式エラー: 確認待ちに戻してから読み込む。
   - 深さエラーになったときは、ここで止める。再巡回は始めない。
3. 読み込み後の状態が巡回中または巡回済なら、状態を「巡回中」にし、再巡回を始める（ここまでは週次の再巡回と同じ）。
4. そのサイトマップのページを、待ち時間なしで最大 170 秒（`MANUAL_BUDGET_SECONDS`）取得する。取り切れなかった分は毎分の処理が続きを取得する。
5. 状態、エラーメッセージ、掲載数、巡回日時を返し、画面を更新する。巡回中で無視したときも、今の状態を返す。

- HTTP リクエストの中で同期的に実行する。
- 押した時点で巡回中のサイトマップは対象外。毎分の処理がそのまま続ける。一覧の「今すぐ巡回」は、巡回済みのときに押した直後と同じ灰色のまま押せない。
- sitemap.xml の読み込みは、ほかの処理と重ならない（「2. sitemap.xml の読み込み」の「同時に読み込まない」）。
- ページの取得は、毎分の処理との排他はない。同時に動くと、同じページを二重に取得することがある。

### サイトマップ詳細の「今すぐ巡回」

実装: `SitemapController::crawl`

- 1ページだけをその場で取得し直す。sitemap.xml は読まない。レスポンスの SHA-256 が前回と同じで、採用本文のハッシュに一致するベクトル行があるときは、抽出もベクトル化もせずに終わる。本文が同じでベクトルが無いときは抽出せず、ベクトル化する。本文が違えば抽出し、採用本文のハッシュが前回と同じでベクトル行があるときだけベクトル化を省く。
- 接続できなかったときの扱いは「4. ページの取得」と同じ。取得済みのページなら、取得日時と抽出結果は前回のまま残す。

## 7. その他

- 検索に出すページは、掲載中、検索対象が ON、本文があるもの（`SitemapPage::scopeForSearch`）。抽出状態は見ない。検索対象はページごとに詳細画面で切り替えられる。初期値は ON。
- サイトマップを削除すると、そのページもすべて削除する。
