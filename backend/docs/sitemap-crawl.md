# サイトマップの登録と巡回

2026-10-16 時点の実装をそのまま仕様として書いたもの。

## 全体の流れ

処理は3つに分かれ、それぞれ別の定期実行で動く。

1. サイトマップの読み込み（毎時）: 未読か、前回の読み込みから1日経った sitemap.xml を読み、掲載 URL を `sitemap_pages` に同期する。外れた URL は設定回数に応じて削除する。
2. ページの取得と本文抽出（毎分）: 未取得か、前回の取得から7日経ったページを1秒に1ページずつ取得し、本文を抜く。
3. ベクトル化（毎分）: 採用本文のハッシュに合うベクトル行が無いページをベクトル化する。

2と3の失敗は、続くほど次の再試行を遅らせる（「8. 再試行の待ち時間」）。各処理のエラーは `crawl_error_logs` に記録する（「9. エラーのログ」）。

## サイトマップの状態

| 状態 | 値 | 意味 |
| --- | --- | --- |
| 確認待ち | `pending` | 登録直後。まだ sitemap.xml を読めていない |
| 巡回済 | `completed` | sitemap.xml を一度以上読めた |
| 取得失敗 | `failed` | 初回の読み込みで sitemap.xml を取得できなかった |
| 書式エラー | `invalid` | 初回の読み込みで sitemap.xml の書式が正しくなかった、または深さが上限を超えていた（深さエラー） |

- 状態はサイトマップの読み込みの結果だけを表す。ページの取得やベクトル化が終わったかは表さない。
- 一覧の状態の列は、`error_message` があればそれを赤字で出し、なければ状態名を出す。
- 2回目以降の読み込みで深さエラーになったときは、状態は「巡回済」のまま変えず、`error_message` だけを残す。次の読み込みが成功すると、メッセージは消える。

遷移:

- 確認待ち → 巡回済: 読み込みに成功した
- 確認待ち → 取得失敗 / 書式エラー: 読み込みに失敗した（深さエラーは書式エラーになる）
- 取得失敗 / 書式エラー → 確認待ち: 「今すぐ巡回」を押した（すぐに読み込みをやり直す）

## 1. 登録

- 管理画面のサイトマップ一覧から URL を登録する。
- URL は http または https。登録済みの URL は登録できない（URL 文字列の SHA-256 で一意）。
- 登録時に sitemap をたどり、深さが上限を超えていればエラーを表示して保存しない。取得失敗や書式の不正は、ここでは止めずに「確認待ち」で保存する。
- 深さの問題がなければ「確認待ち」で保存する。掲載 URL の取り込みは、次の毎時の読み込みか「今すぐ巡回」で行う。
- 外れた URL を削除するまでの回数（`absence_limit`）の初期値は 1 回。

## 2. sitemap.xml の読み込み

実装: `sitemaps:inspect`、`App\Jobs\InspectSitemap`、`App\Services\SitemapTreeReader`、`App\Services\SitemapUrlsetReader`

- 対象は、状態が「確認待ち」か「巡回済」で、`sitemaps.crawled_at` が空か1日より前のサイトマップ。毎時動く。
- 「取得失敗」と「書式エラー」は自動では読み直さない。「今すぐ巡回」でのみやり直す。

### 書式

- ルート要素が `urlset` または `sitemapindex` で、名前空間 `http://www.sitemaps.org/schemas/sitemap/0.9` を宣言していること。
- 各 `loc` が http または https の URL であること。1件でも不正な `loc` があれば、そのファイル全体を書式エラーとする。
- `loc` が1件もないファイルは書式エラー。
- `lastmod` などの `loc` 以外の要素は使わない。
- 外部エンティティは読まない（`LIBXML_NONET`）。
- ファイルサイズの上限はない。

### ネスト

- `sitemapindex` に載っている子 sitemap を再帰的に読む。
- 登録した sitemap を深さ 1 とし、深さ 5（`InspectSitemap::MAX_DEPTH`）まで読む。
- 上限より深い子 sitemap があるときは、その URL は読まず、読み込み全体を深さエラーにする。メッセージは「sitemap の深さが 5 を超えています。」。
- 登録時: フォームにエラーを出して保存しない。
- 確認待ちからの読み込み: 状態を「書式エラー」にし、`error_message` に残す。ページは同期しない。
- 巡回済からの読み込み: 状態とページは変えない。`error_message` に残す。次の読み込みが成功したら `error_message` は消える。
- すでに読んだ sitemap の URL が上限より深い位置に再度出ても、深さエラーにはしない。
- 同じ sitemap の URL は1回だけ読む。
- 子 sitemap が1つでも取得失敗または書式エラーなら、その回の読み込みは全体を失敗とし、何も同期しない。

### 重複

- 掲載 URL は、全階層をまとめたうえで重複を除く。
- 重複の判定は URL 文字列の完全一致。末尾のスラッシュやフラグメント（`#`）の違いは別の URL として扱う。
- ページは sitemap ごとに一意（`sitemap_id` と URL の SHA-256）。別のサイトマップに同じ URL があれば、別の行として持つ。

### 同時に読み込まない

- 同じサイトマップの読み込みと同期は、同時に1つまで。毎時の読み込みと「今すぐ巡回」のどちらにも効く。
- `InspectSitemap` がサイトマップごとのロック（キャッシュのロック、キー `sitemap-inspect:{id}`）を取ってから読む。ロックの期限は 600 秒（`InspectSitemap::LOCK_SECONDS`）。
- ロックを取れなかった側は、sitemap.xml を読まず、状態もページも変えずに戻る。不在回数も数えない。
- ロックの中で状態を読み直してから処理する。

### HTTP

- タイムアウトは 30 秒、接続タイムアウトは 10 秒。User-Agent は `miune`。
- 2xx 以外のレスポンスは取得失敗とする。

### 失敗したとき

- 初回（確認待ちからの読み込み）: 状態を「取得失敗」または「書式エラー」にし、エラーメッセージを保存する。
- 2回目以降（巡回済からの読み込み）: 状態もページも変えない。取得失敗と書式エラーは画面に出ない。深さエラーだけは `error_message` に残る。
- どの失敗も `crawl_error_logs` に記録する。
- 読み込みに成功したとき、サイトマップの巡回日時（`sitemaps.crawled_at`）をその時刻にする。失敗したときは前回のまま残すので、巡回済のサイトマップは次の毎時の回に読み直す。
- サイトマップ一覧では、「削除までの回数」の右に `Y-m-d H:i` で出す。ページの取得日時とは別。

## 3. 掲載 URL の同期

読み込みに成功したとき、掲載 URL と `sitemap_pages` を突き合わせる。

### sitemap に載っている URL

- 新しい URL: 行を追加する。取得日時が空なので、毎分の取得の対象になる。
- 既存の URL: 何もしない。
- 一度外れて戻ってきた URL: 不在回数を 0 に戻し、掲載中に戻す。本文がなければ取得日時を空にして取得の対象にする。

### sitemap から外れた URL

- 不在回数（`absence_count`）を 1 増やし、初めて外れたときは外れた日時（`unlisted_at`）を記録する。
- 不在回数が `absence_limit` に達したら、その行を削除する。
- `absence_limit` は 1〜5 回、または「削除しない」（`null`）。サイトマップ一覧で変更できる。
- 「削除しない」の場合、外れた URL は行として残り、検索には出ない。
- 読み込みに失敗した回は数えない。取得エラーで一斉に削除されることはない。
- 回数を減らしても、すぐには削除しない。次の読み込みで判定する。

## 4. ページの取得

実装: `sitemaps:crawl`、`App\Services\CrawlDueSitemapPages`、`App\Jobs\CrawlSitemapPage`

- 対象は、掲載中のページのうち、次の両方に当てはまるもの。ID 順に取得する。1回の実行では同じページを繰り返さない。
  - 未取得（`crawled_at` が空）か、取得日時が7日（`CrawlDueSitemapPages::RECRAWL_DAYS`）より前
  - 再試行の待ち（`fetch_retry_at`）が空か、過ぎている
- 1秒に1ページ（`INTERVAL_SECONDS`）。1回 55 秒（`BUDGET_SECONDS`）で打ち切り、残りは次の回に回す。
- タイムアウトは 30 秒、接続タイムアウトは 10 秒。User-Agent は `miune`。
- HTTP 404 以外は、HTTP ステータス、サイズ、本文、本文の SHA-256、取得日時を保存する。2xx 以外のレスポンスも保存する。本文は Content-Type または HTML の meta charset に従って UTF-8 に変換し、文字コード指定がなく UTF-8 でもない場合は日本語の主要な文字コードを判定する。`body_sha256` は変換後の保存本文から計算する。
- 保存する本文の meta charset は UTF-8 に書き換える。ヘッダと meta charset が食い違っていても、後から `sitemaps:extract` で抜くときに同じ文字コードで読める。
- 本文を UTF-8 に変換できなければ本文は保存せず、「文字コードを UTF-8 に変換できません。」とし、抽出状態を「抽出失敗」にする。取得日時は入れるので、取り直しは7日後。
- 本文が 2MB（`CrawlSitemapPage::MAX_BODY_BYTES`）を超えたら本文は保存せず、「レスポンスが大きすぎます。」とする。取得日時は入れるので、取り直しは7日後。
- 接続できなかったとき、または HTTP 404 のときは「取得に失敗しました。」とし、取得失敗の回数（`fetch_failure_count`）を 1 増やして、再試行の待ち（`fetch_retry_at`）を決める（「8. 再試行の待ち時間」）。取得日時、本文、HTTP ステータス、抽出結果は前回のまま残す。一度も取得していないページは、取得日時が空のまま。404 の本文は保存せず、抽出しない。
- 404 以外のレスポンスを受け取れたら（2xx 以外も含む）、取得失敗の回数を 0、再試行の待ちを空に戻す。
- ページの取得ではベクトル化しない。

### 本文の抽出

実装: `App\Services\ExtractSitemapPage`、`App\Services\ReadabilityTextExtractor`、`App\Services\TrafilaturaTextExtractor`、`App\Services\ExtractionComparison`

- UTF-8 に変換したレスポンスを保存できた直後に、Readability と Trafilatura で本文を抜く。保存したレスポンスは `body` に残す。検索の条件は変えない。
- 保存前の `body_sha256` と、今回の本文の SHA-256 が同じときは、抽出済み（`extracted_at` があり「抽出失敗」でない）なら抜かない。採用した本文と抽出状態は前回のまま残す。未抽出または「抽出失敗」なら抜き直す。
- 本文が変わったときは、保存と同時に以前の採用本文、抽出状態、抽出日時を消してから抜き直す。抽出中に予期しないエラーが起きても以前の本文は残さず「抽出失敗」にし、`crawl_error_logs` に記録する。
- 抽出が失敗しても、取得の成否は変えない。
- 採用は `ExtractSitemapPage::adoptedText()`。保存した本文は `SitemapPage::articleText()` で読む。
  - 両方の抽出器が空でない本文を返したときだけ比べる。空白を畳んだ文字3-gramの Jaccard 係数が 0.8 以上なら一致、未満なら不一致とみなす。閾値は `ExtractionComparison::MINIMUM_SIMILARITY`。
  - 一致したときは Trafilatura の本文を採用する。差は小さいので、どちらを使っても同じ本文とみなす。
  - 不一致の分岐は残し、将来はそこで ChatGPT に両方の本文を渡す。このプロジェクトはデモのため、課金を避け、その分岐では Trafilatura が抽出した文字列を返す。
  - 片方の抽出器だけ異常終了したとき、または片方だけ本文を見つけたときは、取れた側の本文を採用する。
- 抽出状態 `extraction_status` は次の2つだけ保存する。本文を採用できたときと未抽出のときは空。一致と不一致は保存しない。
  - 「本文なし」: 採用した本文が空文字。
  - 「抽出失敗」: HTML でないレスポンス、文字コードを UTF-8 にできないレスポンス、両方の抽出器が異常終了したとき。採用した本文は残さない。
- 保存するのは採用した本文 `article_text` だけ。Readability、Trafilatura、将来の ChatGPT が抽出した文字列は、それぞれは保存しない。
- 採用した本文が空でないときは、その SHA-256 を `article_text_sha256` に保存する。本文がないとき、空文字のときは空にする。保存のたびに `article_text` から計算する。
- ハッシュが空になった保存では、そのページのベクトル行をすべて消す。抜き直しの直前に本文を空へ戻すときだけは、ベクトル行を残す。抜き直して同じ本文になれば、ベクトル化をやり直さずに済む。
- 掲載URL一覧には、抽出状態の列も絞り込みも出さない。
- プレーンテキストの先頭行がページの `title` と一致するときは、比較の前にその行を落とす。
- Trafilatura はアプリイメージの `/opt/trafilatura` で動かす。HTML は標準入力で渡し、Trafilatura からは URL を取得しない。
- 本文を保存しなかったページ（大きすぎる、未取得）は抽出しない。大きすぎるページを取り直したときは、前回の抽出結果を消す。
- 保存済みの本文だけを後から抜くコマンドは `sitemaps:extract`。対象は本文があり、`extracted_at` が空、または「抽出失敗」のページ。本文を一度に読み込みすぎないよう10件ずつ処理する。定期実行はしない。保存済みの本文は UTF-8 なので、本文中の指定と UTF-8 の判定だけで処理する。ベクトル化はしない。

## 5. ベクトル化

実装: `sitemaps:embed`、`App\Services\EmbedPendingSitemapPages`、`App\Services\EmbedSitemapPage`

- 対象は、次のすべてに当てはまるページ（`SitemapPage::scopeMissingEmbedding` と再試行の待ち）。ID 順に処理する。1回の実行では同じページを繰り返さない。
  - 採用本文のハッシュ（`article_text_sha256`）がある
  - そのハッシュのベクトル行が `sitemap_page_embeddings` に無い
  - `embedding_failed_sha256` がその本文ハッシュではない
  - 再試行の待ち（`embedding_retry_at`）が空か、過ぎている
- どの処理で本文が変わっても、ハッシュの差で対象になる。ベクトル化を頼む表は持たない。
- 1回 55 秒（`EmbedPendingSitemapPages::BUDGET_SECONDS`）で打ち切る。
- OpenAI の埋め込み API（`text-embedding-3-small`、1536 次元）を呼ぶ。送る本文は先頭 4000 文字まで。チャット API は使わない。成功してから、そのページのベクトル行をすべて入れ替える。
- ベクトルは `sitemap_page_embeddings` に保存する。同じページの行を複数持てる。今回の分割は本文全体の1行だけで、段落には分けない。行の順番は持たない。
- 本文が変わってからベクトル化が終わるまでは、そのページは検索に出ない。検索は本文ハッシュの一致するベクトル行だけを使うため。

### 失敗したとき

- タイムアウト、429、5xx などの一時的な失敗: `embedding_error` にメッセージを残し、ベクトル化の失敗回数（`embedding_failure_count`）を 1 増やして、再試行の待ち（`embedding_retry_at`）を決める。古いベクトル行は残す。
- 長さ超過のように同じ本文では成功しない失敗: `embedding_failed_sha256` にその本文ハッシュを残す。その本文では呼び直さない。失敗回数と再試行の待ちは戻す。
- API キーが未設定、または認証に失敗したとき: ページの問題ではないので、ページの失敗回数は増やさない。その回の処理を止め、キャッシュ（`embedding-auth:failures`、`embedding-auth:retry-at`）に失敗回数と再試行日時を持ち、同じ倍々の待ち時間で処理全体を待たせる。どれかのページを API に送れた回で、この待ちを消す。
- 成功したら、`embedding_error`、`embedding_failed_sha256` を空にし、失敗回数を 0、再試行の待ちを空に戻す。
- どの失敗も `crawl_error_logs` に記録する。

## 6. 定期実行

実装: `routes/console.php`。`miune_scheduler` コンテナで `php artisan schedule:work` が動く（cron は使わない）。

| コマンド | 間隔 | 内容 |
| --- | --- | --- |
| `sitemaps:inspect` | 毎時 | 「2. sitemap.xml の読み込み」と「3. 掲載 URL の同期」 |
| `sitemaps:crawl` | 毎分 | 「4. ページの取得」 |
| `sitemaps:embed` | 毎分 | 「5. ベクトル化」 |

- どれも重複起動しない（`withoutOverlapping`）。
- 読み込みは毎時動くが、対象は前回の成功から1日経ったものだけなので、同じサイトマップを1日に2回読んで不在回数を二重に数えることはない。

## 7. 今すぐ巡回

### サイトマップ一覧の「今すぐ巡回」

実装: `SitemapController::crawlNow`

1. ロックを取る。取れなければ、sitemap.xml は読まず、状態もエラーメッセージも変えない。
2. 取得失敗 / 書式エラーなら、確認待ちに戻してから読む。巡回済と確認待ちはそのまま読む。巡回日時は見ない。
3. sitemap.xml を読んで掲載 URL を同期する（「2. sitemap.xml の読み込み」と同じ）。ページの取得とベクトル化はしない。
4. 状態、エラーメッセージ、掲載数、巡回日時を返し、画面を更新する。

- HTTP リクエストの中で同期的に実行する。
- sitemap.xml の読み込みは、ほかの処理と重ならない（「同時に読み込まない」）。

### サイトマップ詳細の「今すぐ巡回」

実装: `SitemapController::crawl`

- 1ページだけをその場で取得し直す。sitemap.xml は読まない。再試行の待ちは無視する。取得と本文の抽出は「4. ページの取得」と同じで、結果に応じて取得失敗の回数を増やすか 0 に戻す。
- ベクトル化はしない。本文が変われば、次の毎分のベクトル化で処理する。

## 8. 再試行の待ち時間

実装: `App\Support\RetryBackoff`

- 連続した失敗回数を n とすると、次に試すまでの待ち時間は 2 の (n-1) 乗分。1分、2分、4分、8分…と倍にし、24時間（`RetryBackoff::MAX_MINUTES`）で止める。12回目以降は24時間。
- ページの取得、ページのベクトル化、ベクトル化の認証エラーで、それぞれ別に数える。成功したら 0 に戻す。
- サイトマップの読み込みは毎時なので、待ち時間は付けない。

## 9. エラーのログ

実装: `App\Models\CrawlErrorLog`、`App\Enums\CrawlErrorKind`

- 3つの処理のエラーを `crawl_error_logs` に1行ずつ記録する。画面からは見られない。
- 種別（`kind`）は `sitemap`、`page`、`embedding`。
- サイトマップ ID、ページ ID、記録したときの URL、HTTP ステータス、メッセージ、記録日時を持つ。ベクトル化の認証エラーはページに結び付かないので、ID と URL は空。
- サイトマップやページを削除しても、ログは残す。ID だけ空にする。
- 古いログは自動では消さない。
- `sitemaps.error_message`、`sitemap_pages.error_message`、`sitemap_pages.embedding_error` は、画面に出す最新の状態として別に持つ。

## 10. その他

- 検索に出すページは、掲載中、検索対象が ON、本文があり、HTTP ステータスが 404 ではないもの（`SitemapPage::scopeForSearch`）。抽出状態は見ない。検索対象はページごとに詳細画面で切り替えられる。初期値は ON。
- サイトマップを削除すると、そのページもすべて削除する。
