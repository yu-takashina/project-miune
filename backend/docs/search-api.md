# 検索 API

2026-10-20 時点の実装をそのまま仕様として書いたもの。管理画面右上の検索は、「ベクトル検索の対象」と同じ条件で探す。レスポンスと回数の制限は検索 API だけのものである。

## エンドポイント

`GET /api/search`

クエリ `q` に検索語を渡す。本文は受け取らない。レスポンスは JSON で、セッションは開始しない。

```
GET /api/search?q=梅雨
Authorization: Bearer {APIキー}
```

成功時は配列を返す。関連度は付けない。ベクトル検索でも部分一致でも形は同じで、どちらで探したかは返さない。

```json
[
  {
    "url": "https://example.com/rain",
    "article_text": "今日は梅雨です"
  }
]
```

一致が無いときも 200 で、空の配列を返す。

| フィールド | 意味 |
| --- | --- |
| `url` | ページの URL。同じ URL と、採用本文が同じ別の URL は 1 件だけ返す |
| `article_text` | 採用した本文の先頭 500 文字（`Api\SearchController::ARTICLE_TEXT_LENGTH`）。文字数は Unicode の字数で数え、短い本文はそのまま返す。切ったことを示す印は付けない。抽出器ごとの文字列は返さない |

最大 10 件。

## 認証

`Authorization: Bearer {APIキー}` を付ける。`Bearer` の大文字小文字は問わない。

APIキーは 32 文字で、使える文字は英数字と `+` `-` `_` だけ。大文字小文字は区別する。合わない、無い、無効化したキーは 401 で、検索も回数の加算もしない。

```json
{ "message": "APIキーが正しくありません。" }
```

検索が 200 で終わったときだけ、そのキーの最終利用日時を更新する。

## 検索語

前後の空白は除く。空白だけは空とみなす。文字数は Unicode の字数で数える。

| 状態 | レスポンス |
| --- | --- |
| 空 | 422 `{ "message": "検索語を入力してください。" }` |
| 201 文字以上 | 422 `{ "message": "検索語は200文字以内で入力してください。" }` |

この 2 つは、あとの回数に入れない。

## 探し方

1. 同じ検索語・同じ埋め込みモデルのベクトルが保存済みなら、それを使ってベクトル検索する。OpenAI は呼ばない。回数にも入れない。
2. 保存が無いときは、検索 API 全体で直近の 1 分間に 60 回まで、その検索語をベクトル化して保存し、ベクトル検索する。APIキーごとではない。
3. ベクトル化が 60 回を超えたあとは、OpenAI を呼ばず、`article_text` の部分一致で探す。この部分一致も、検索 API 全体で直近の 1 分間に 60 回まで。
4. 部分一致も 60 回を超えたときは 429 を返し、中身は返さない。

```json
{ "message": "リクエストが多すぎます。" }
```

429 には `Retry-After` を付ける。秒数は、部分一致の回数が解けるまでの時間。

1 分間は、その回数の最初の 1 回から 60 秒。ベクトル化と部分一致は別々に数える。回数は先に 1 足し、足したあとの値が 60 以下のときだけ通す。同時に来た別の検索語でも 60 を超えない。上限を超えて断ったリクエストも、その回数には入る。

同じ未登録の語が同時に来たときは、1 回のベクトル化にまとめる。後から来たリクエストは、保存されたベクトルを使う。

埋め込み API の呼び出しに失敗した回も、ベクトル化の回数に入る。失敗した語は保存しない。

埋め込みモデルを変えると、同じ語でも新しいベクトル化になる。既定のモデルは `text-embedding-3-small`。

## ベクトル検索の対象

近い順に最大 10 件。距離は返さない。

対象は、次のすべてに当てはまるページ。管理画面右上の検索も、この条件で探す。

- 掲載 URL の検索対象が ON である
- サイトマップの検索対象が ON である
- サイトマップから外れていない
- 取得した本文がある
- HTTP ステータスが無い、または 404 ではない
- 取得失敗が続いていない、または最後に取得できてから 10 日経っていない
- 今の採用本文のハッシュと一致するベクトル行がある

ベクトル索引は使わず、条件に合うページをすべて比べる。索引は近似で、本当に近いページを取りこぼすため。条件で絞ってから並べるので、同じ URL と同じ採用本文を除いて 10 件以上あれば、必ず 10 件返す。

距離は Laravel のクエリビルダーの `selectVectorDistance` で求める。MariaDB の余弦距離（`VEC_DISTANCE_COSINE`）になる。クエリビルダーのベクトル機能は接続が `mariadb` のときだけ使えるので、`.env` の `DB_CONNECTION` は `mariadb` にする。`mysql` にすると、相手が MariaDB でも検索は例外になる。

同じページに複数のベクトル行があれば、最も近い行の距離を使う。同じ URL のページと、採用本文が同じ（`article_text_sha256` が一致する）ページは、最も近いページだけを残し、距離が同じならページ ID が小さい方を残す。サイトは同じ記事を別の URL（カテゴリ配下の URL など）でも載せているため、URL だけでは重複を除けない。どの URL を残すかは、サイトの canonical 指定を見ない。

かかる時間はページ数に比例する。1648 ページで 1 回 0.13 秒ほど。

## 部分一致の対象

`article_text` に検索語が含まれるページを、ページ ID の小さい順に最大 10 件。同じ URL のページと、採用本文が同じページは、ID が小さい方を残す。

対象は、次のすべてに当てはまるページ。

- 掲載 URL の検索対象が ON である
- サイトマップの検索対象が ON である
- サイトマップから外れていない
- 取得した本文のハッシュがある
- HTTP ステータスが無い、または 404 ではない
- 取得失敗が続いていない、または最後に取得できてから 10 日経っていない
- 採用本文がある

`%`、`_`、`\` はワイルドカードにせず、文字どおり探す。大文字と小文字、ひらがなとカタカナ、濁点と半濁点は区別しない。ベクトル化がまだのページも、上の条件に合えば返す。

探すのは本文全体なので、返す `article_text`（先頭 500 文字）に検索語が含まれるとは限らない。

## 埋め込みに失敗したとき

ベクトル化を試みたあとで失敗したときは 503。部分一致には切り替えない。`message` は次のいずれか。

| メッセージ | とき |
| --- | --- |
| `OPENAI_API_KEY が未設定です。` | API キーが未設定 |
| `OpenAI の認証に失敗しました。` | 認証に失敗した |
| `埋め込み API に接続できません。` | 接続できない |
| `埋め込み API が失敗しました。` | それ以外の呼び出し失敗、または同じ語の処理待ちがタイムアウトした |
| `埋め込みを保存できません。` | ベクトルを保存できない |
| `埋め込みの次元が不正です。` | 受け取ったベクトルの次元が 1536 ではない |
